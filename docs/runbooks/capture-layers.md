# 捕获层验收

系统代理与 TUN 两层在三个桌面平台上的系统验收步骤。层模型与切换规则见
[捕获层切换](../architecture/runtime.md#捕获层切换)；macOS 的数据面、旧连接与长时间运行检查另见
[macOS TUN 验收](macos-tun.md)。

## 网络影响与准备

验收会改变系统代理设置、新增 TUN 接口与默认捕获路由、修改 DNS，并启停防火墙对象（Windows WFP、
Linux nftables）与特权服务。只在测试虚拟机中执行，执行前说明这些影响；每次运行设置超时，
使连接中断时恢复仍能完成，结束后核对网络状态。

开始前保存基线：系统代理设置、接口与默认路由、DNS、防火墙对象、服务状态和 Runtime 检查点
目录。测试档案使用 `PROCESS-NAME,<命令行客户端>,REJECT` 与 `MATCH,DIRECT`，Fake-IP 池选一个与宿主
不同的网段（例如 `198.19.0.1/16`），以免把宿主代理返回的虚拟地址误当成 Egrio 的结果。

准备两类客户端，并以运行桌面的同一用户启动，进程归因才有意义（Windows 的提权进程对非提权桌面不可
见）：一类遵循系统代理（Windows 的 PowerShell 请求、macOS 的 `nscurl`、Linux 的 GNOME 应用或带
`https_proxy` 的程序），另一类不遵循（`curl`）。开关通过界面或测试构建的控制口（见[桌面宿主](../architecture/desktop.md#测试与验证)）
触发。

## 矩阵

| 步骤 | 操作 | 期望 |
| --- | --- | --- |
| A | 两层关闭 | 无 listener；客户端直连；各项等于基线。 |
| B | 只开系统代理 | 系统代理指向 listener；遵循代理的客户端经 listener（HTTPS 为 `http-connect`，明文 HTTP 为 `http-forward`），进程规则对其生效；不遵循的客户端直连。 |
| C | 两层同开 | TUN 的路由、DNS 与防火墙就位；遵循代理的客户端仍经 listener，其余流量进入 TUN 并按规则处理；Core generation 不变。 |
| D | 只开 TUN | 系统代理逐值回到基线；所有客户端经 TUN；listener 随 Core 保留。 |
| 切换 | 在 B、C、D 之间切换，并在一个限速长下载进行中切换 | Core generation 与 listener 不变；已建立连接按捕获层切换的规则保持或切断。 |
| E | 两层关闭 | Core 停止；接口、路由、DNS、防火墙、系统代理与检查点逐项回到基线。 |
| F | 制造平台失败后开启 TUN | 报告错误并回到切换前的层，Core 不变，无残留。 |
| G | 两层同开且下载进行中，强杀特权服务 | 立即显示 TUN 中断并原地恢复，系统代理与下载不中断；环境无法恢复时，四次尝试后报告失败。 |
| 守护（Windows） | 外部程序反复改写系统代理 | 前三次被改回，第四次让出，层变为只开 TUN，Core 不变。 |
| 退出 | 两层同开时经托盘或应用菜单退出 | 退出清理完成后进程才结束，各项回到基线。 |
| 崩溃 | 两层同开时强杀桌面进程，再重新启动 | 崩溃期间的网络状态符合平台文档的说明；重新启动后检查点清除，各项回到基线。 |

每一步同时核对连接表：所有行来自同一 Runtime Core，连接 id 带 `core-<generation>-` 前缀，`inbound`
区分 `tun` 与 listener 入站；两层同开时同一快照同时出现两类连接且没有重复行；连接详情显示进程、规则、
出站与出口接口。

## 记录

验收结束后替换对应平台文档的“验证状态”：日期、环境、构建、已覆盖与未覆盖范围。未修复的发现写入
[待办](../backlog.md)。原始输出只留在系统临时目录，不写进项目目录，凭据不进入仓库。
