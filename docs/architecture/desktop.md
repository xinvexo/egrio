# 桌面宿主

桌面应用由三个 crate 组成：

- `desktop/egrio-desktop` 是产品后端与 Runtime 宿主：持有配置档案、设置、进程唯一的固定 Runtime 与连接历史，
  提供宿主给用户的操作，不链接任何界面工具包；
- `desktop/egrio-ui` 是界面：Egrio 自己的组件、比对、各窗口与托盘菜单的描述、文本与流量曲线的几何，同样不链接
  界面工具包，页面、比对与文本的测试在任何系统上都能跑；
- `desktop/egrio` 是应用：进程入口、事件循环与三个平台后端，`macos/` 经 AppKit、`windows/` 经 WinUI 3、`linux/`
  经 GTK 4 与 libadwaita 把组件实现为原生控件（见各平台文档的
  [macOS 原生界面](../platforms/macos.md#sdk-与验证依据)、[Windows 桌面应用](../platforms/windows.md#桌面应用)与
  [Linux 桌面应用](../platforms/linux.md#桌面应用)）。

长期网络状态、捕获与恢复属于 [Runtime](runtime.md) 与平台层，界面不持有它们。各 crate 都不提供重导出门面：代码在
使用位置直接导入 `egrio-daemon`、`egrio-platform` 和平台 crate，桌面 crate 不会成为共享 API 的所有者。

支持的系统：Windows 10 22H2（19045）起与 Windows 11，WinUI 3 随系统里安装的 Windows App SDK 运行时提供，
两个系统上是同一套控件；macOS 13 起，注册特权服务的 SMAppService 从 13 开始提供；Ubuntu 24.04 起，由 glibc
2.39 的下限决定，界面只用该版本带的 GTK 4.14 与 libadwaita 1.5 已有的 API。

## 产品后端

- `profile_store.rs` — 用户状态持久化，契约见[配置档案存储](profile-store.md)；
- `remote_fetch.rs` — 远程文档下载：从 URL 一次性导入配置、规则集与 GEODATA 文件。URL 只允许
  http/https、不含内嵌凭据，字面量的 loopback/私网/link-local/ULA 等主机地址被拒绝（复用 Core 的
  `is_forbidden_direct_destination`）；重定向按跳数与目的地双重限制，每一跳都重跑同一校验。配置与
  规则集共用 32 MiB 响应上限和 20 秒总时限，同时检查 `Content-Length` 和流式累计字节数；数十 MiB 的
  文件改按停滞判断（30 秒没有新数据即失败），总时限 15 分钟。下载不绑定物理接口，TUN 开启时与其他
  应用一样进入 TUN，按当前模式出站，全局模式下解析与连接都经代理。导入配置的请求以
  `Egrio/<版本> (clash.meta)` 作为 User-Agent：订阅服务可能按客户端标记选择返回格式，`clash.meta` 是请求支持的
  Clash 配置类型所需的兼容标记；不识别该标记的服务可能返回 base64 分享链接列表。答复是分享链接列表时导入以明确的原因失败，不当作 YAML 去解析；
- `profile_service.rs` — 配置档案在存储上的读写；
- `profile_source.rs` — 一次解码来源中支持的 Clash 字段：节点、分组、规则、provider 定义与
  DNS，范围见[支持的 Clash 字段](profile-store.md#支持的-clash-字段)；`yaml_problem` 用解码的同一个
  YAML 解析器给出来源的第一个错误与位置，供编辑器检查；`edit.rs` 对来源做保留格式的定点改写（顶层设置与
  `rules` 列表）；
- `configuration.rs` — 唯一的配置合成入口，把 Profile 来源与使用中的选择（模式、节点、全局
  出口）合成最终值；
- `profile_configuration.rs` — 局部配置操作的类型化意图，执行边界见
  [桌面配置操作](runtime.md#桌面配置操作与生效状态)；
- `profile_network_settings.rs` — 从同一个最终快照投影监听与 IPv6 设置并生成只读
  `ProfileNetworkSettings`；字段验证和持久来源见[取值规则与作用域](profile-store.md#取值规则与作用域)；
- `app_paths.rs` — 应用数据目录，环境变量 `EGRIO_DATA_DIR` 非空时改用它指定的目录；Core 配置由 Runtime
  core config source 在内存中提供，不落盘交接；
- `runtime.rs` — `DesktopRuntime`：固定 Runtime 的装配、启动恢复、[捕获层切换](runtime.md#捕获层切换)、
  会话丢失恢复与退出 stop。平台只经 `DesktopHost` 契约提供 SDK 装配、topology 与恢复
  （`runtime/windows.rs`、`macos.rs`、`linux.rs`），三个平台共用 `host_lifecycle.rs` 的准入边界，
  见[平台装配](runtime.md#平台装配)；`runtime/tests.rs` 经测试宿主在每个平台验证这些共用行为。进程只有
  一个 `DesktopRuntime`，比发起它的操作活得久的后台工作（GEODATA 下载完成后重启配置）经它到达正在
  运行的配置。Core 的 fake-IP 映射保存在应用数据目录的 `fake-ip-mappings`（见 [Core](core.md)），应用
  重启后仍拿着旧 fake IP 的程序到达原来的域名；这份文件含访问过的域名，只留在本机；
- `tun_environment.rs` — TUN 模式的一次性环境：Windows 特权服务正在运行、注册的可执行文件是本应用
  目录中的 `egrio-service.exe` 且 `wintun.dll` 在旁；macOS 应用包携带的 launchd 服务以本应用的协议
  应答；Linux 的 systemd 单元正在运行、服务当前用户且安装的助手与本应用旁的 `egrio-service` 逐字节
  相同。检查从不打开 TUN 设备；准备在需要时提示用户（Windows UAC、macOS 在“登录项”中允许服务、
  Linux 经 `pkexec` 的 polkit 授权）。各平台细节见平台文档；
- `network_probe.rs` — 面向用户的 IP/延迟探测；出口 IP 探测显式通过当前 Runtime Core listener，
  不读取 OS system proxy；IPv4/IPv6 各自使用多个地址族专用端点顺序回退，DTO 同时保留每族的可用
  地址或完整失败原因。探测服从当前 profile 的流量策略：两个捕获层只决定哪些流量进入 Core，流量
  策略独立决定进入后的 DIRECT/代理出站；
- `ipv6_settings.rs` — Windows 独立的 tunnel/block/off 姿态 DTO，从本代捕获保存快照投影 IPv6 是否
  进入 Wintun 或被 WFP 阻断，不使用配置档案的 IPv6 解析开关决定姿态；
- `geodata.rs` — GEOIP 与 GEOSITE 规则读取的 `geoip.dat`、`geosite.dat`，保存在应用数据目录的
  `geodata/` 下，所有配置共用。来源是 Loyalsoldier 的 v2ray-rules-dat：它的 `geoip:cn` 取自中国大陆
  运营商公布的网段（china-operator-ip），不只是地理数据库的估计；GEOSITE 在 v2fly 域名列表上加入了
  中国大陆列表。先试项目 README 列出的 jsDelivr 镜像，再试 GitHub release，因为代理运行前镜像通常
  更容易访问；下载的文件必须能解码，整份写好并刷到磁盘后改名替换（改名先于内容落盘时，断电会留下
  一个名字正确的空文件，而文件既然在，之后的启动不会再下载），内容未变不重写。启动配置时只把规则用到的
  代码交给 Core；规则用到而文件缺失时，启动不等待，后台下载一次，完成后重启正在运行的配置使其生效。
  同一时间只有一次下载；
- `rule_provider_fetch.rs` — 规则提供程序获取/刷新，单次操作持有同一 HTTP 连接池与每 Profile 刷新
  准入；有可用 Core 时经其内部出站下载，HTTP/TLS 与连接池由 `remote_fetch/core.rs` 接入。
  `runtime/rule_preparation.rs` 拥有首次准备任务、失败与手动重试，缓存检查、内容变化和 Runtime 生效的
  边界见[来源解析与生效](profile-store.md#来源解析与生效)。
  传输连接的实际终止事实与 HTTP 文档更新结果分开报告，不能按已下载字节数把异常终止改成成功；
- `desktop_behavior.rs` — 开机启动、静默启动、启动时检查更新、主题与语言偏好。开机启动在 macOS 上是应用自己的登录项
  （ServiceManagement 的 `SMAppService.mainAppService`，macOS 13 起；用户在系统设置里关掉后要再次允许，打开开关
  时应用带用户去“登录项”），切换时一并删除以前写的 `Egrio` launch agent；Windows 是以 `Egrio` 命名的 `Run` 注册表
  值（值是带引号的可执行文件路径），Linux 是 XDG autostart 项；
- `updates.rs` — Egrio 自己的更新：查询最新的发布、下载并核对本机的安装包，见[更新](#更新)；
- `ui_text.rs` — 界面语言：存储的语言偏好，“跟随系统”时读系统语言（`sys_locale`），`zh` 开头为中文，其他为
  英文，取不到时为中文；
- `models.rs` — 界面常用的配置与出口 DTO；
- `operations/` — 宿主给用户的操作，分为 `capture`、`egress`、`profiles`、`settings` 与 `telemetry`：
  参数映射加 Runtime 宿主与存储调用，不自行持有 `CoreSessionManager`、Core generation claim 或第二把
  网络转换锁。节点、模式和 IPv6 走 Runtime 的原地配置更新，allow-lan 走监听组件重载，整份配置替换与
  端口/显式绑定地址修改完整重启；
- `operations/telemetry.rs` — 读取统一 Runtime Core 的状态和遥测 snapshot；listener 与 packet 行共享
  `core-<generation>-` 前缀并靠 `inbound` 区分。宿主启动后 `absorb_connection_history` 每 2 秒以历史保存
  的游标取 Core 的新行并入本进程的连接历史（`connection_history.rs`，上限 5000 行），不论窗口是否显示：
  Core 只留实时表和有界的结束记录环（见 [Core 模块布局](core.md#模块布局)的 `session_registry.rs`），
  等窗口来问会丢掉其间结束的连接；两次吸收之间结束的连接多于记录环时，较早结束的仍会缺失。历史的每次
  变化推进一个修订号，`traffic_connections` 按调用方持有的修订号只返回之后变化与移除的行（没有修订号或
  落后于保留的移除记录时返回全部行），`traffic_totals` 只返回字节累计、活动连接数与进程数（同名程序在
  不同路径算两个）。历史第一次收进一条连接时为它匹配的规则在正在运行的配置下计一次命中，按配置分开
  保存到应用退出或用户重置（`rule_hits`、`reset_rule_hits`）。规则按 Core 报告的那一行文字记（见
  [Core](core.md#模块布局)的 `telemetry.rs`），不按规则 id：id 是规则在某一版文件里的位置，规则页新增的规则
  总是插在最前面，按位置记的命中数和历史连接的规则在每次新增后都会错到相邻的规则上。`traffic_volume` 不经历史，只读 Core 的
  流量总量，并在读取时以单调时钟打戳。历史是空闲应用留得最多的东西，所以它的行处处共享而不复制：一行
  是一块内存，历史和显示它的表一起拿着，表里的那份只是指针；行经一张指针的索引找到，哈希表空着的位置
  只有一个指针大；很多行都带的文字（程序名和路径、规则、出站、反复访问的主机）只留一份；最早结束的行
  超过上限时直接挑出来移除，移除记录留 1024 条，表落后更多就整份重读；
- `operations/capture.rs` — 两个捕获层的操作：`capture_status`（已提交的层、平台支持、TUN 环境是否
  就绪与中断原因）、`set_capture_layer` 与 `toggle_capture_layer`（切换一层）、`prepare_tun_environment`；
  DTO 为 `CaptureStatus`、`CaptureLayersReport` 与 `TunEnvironment`。托盘以同一意图形式切换；开启 TUN
  而环境需要用户批准时如实返回，不改变任何层；
- `events.rs` — 宿主要响应的变化：状态转换落地、配置变化、自动策略组换了成员、TUN 会话与系统代理的
  通知（通知的种类是枚举）。
  它们发布在一个广播通道上，宿主订阅后转给窗口和托盘；信号不带状态，落后的订阅收到一次状态变化与一次配置
  变化来代替丢失的事件，重读界面上的数据即可恢复，只有丢失的通知找不回；
- `async_runtime.rs` — 进程共用的 tokio 运行时，界面的异步操作与后台吸收都在上面运行；
- `policy_watch.rs` — 运行中的 Core 自己决定的那部分策略：每个自动策略组正在用的成员。健康探测与驱逐
  会在用户和配置都没动的时候改变它，而 Core 对此不推进任何宿主能等的东西（一次测速改变 UrlTest 的排名
  并不改变任何在跑的流的路由），所以应用每 5 秒读一次报告，变了就发布事件；它随应用运行，不看有没有窗口，
  因为没有窗口时托盘也在显示这个成员；
- `system_proxy_guard.rs` — Windows adapter guard 事件的接线：reassert 只通知，yield 在用户过渡锁内
  经捕获层切换只移除系统代理层；macOS 与 Linux 不安装 guard；
- `exit.rs` — 退出协调器，见[退出](#退出)；
- `logging.rs` — 日志级别、行格式、日志文件与日志页的历史，见[日志](#日志)；
- `runtime_owner.rs` — 每个用户一个 Runtime 所有者：进程存活期间持有应用数据目录里的
  `runtime-owner.lock`，macOS 与 Linux 都用它；
- `service_control.rs`（macOS）— 由 `EGRIO_MACOS_SERVICE` 选择的一次性服务注册命令（status、register、
  unregister），输出 JSON 后不启动界面；它必须在 Egrio.app 里运行，因为 SMAppService 从调用者的应用包
  注册服务。


## 界面层

`egrio-ui` 只为 Egrio 服务：组件、属性与事件按页面的需要增加，不做通用界面库，不公开 API。页面需要新的界面
元素时，在组件集合里加一项，三个后端各实现一次；页面只写一遍。

### 描述与运行时

每个窗口是从状态到组件树的纯函数（`view.rs`、`pages/`、`editor.rs`）。事件不是闭包而是消息值（`msg.rs`）：
运行时（`runtime/`）按消息修改界面状态，并执行要做的操作（调用 egrio-desktop、请求文件、打开编辑器窗口），
操作的结果作为消息回来。消息是数据，组件树因此可以比较，测试可以断言“按下这个按钮发出这条消息”。

- 界面状态（`state.rs`）只放页面自己的东西：当前菜单、节点页显示的条目、筛选词、选择、排序与分组、对话框与
  表单草稿、编辑器草稿；应用数据只读地取自后端的读取结果。当前菜单与节点页显示的条目存在应用数据目录的
  `interface.json` 里（`remembered.rs`），改变时在后台整份替换；文件缺失或读不懂时从活动页开始。
- 悬停、焦点、滚动位置、提示框与动画这类瞬时状态留在原生控件里，不进界面状态。
- 文本输入由原生控件持有：控件报告每次修改，界面状态记下；只有界面状态与控件最后报告的值不同（例如程序清空
  筛选框）时才写回控件，输入法的组字不被打断。表格的选择同样由原生控件维护并报告，程序改变选择时才写回。
- 开关、分段选择与下拉选择显示界面状态：后端在每次用户事件处理并重绘之后把它们对回界面状态
  （`Backend::settle`），界面拒绝的改动（例如没有配置时切换模式）由此回到原值。
- 改动从点击起就显示它要的值，不先弹回旧值再跳到新值。捕获开关与配置改动（模式、全局出口、组成员、IPv6 与
  局域网）同一时间只跑一个，其间别的改动被拒绝、控件回到原值；改动跑过 0.5 秒还没结束，等它的控件才变灰，
  捕获开关在工具栏上显示为进行中，快的改动因此什么都不闪。改动结束时控件直接显示它的结果（捕获层取操作报告的
  层，配置改动取保存的值），随后读回的状态再确认；失败回到原值并记进消息。偏好（开机自启、静默启动、主题、
  语言）同样立即显示，保存期间别的偏好改动被拒绝，保存失败回到存下的值。开关不带进度环，旁边不出现也不消失
  任何东西；忙碌的按钮原地转进度环、保持尺寸。

### 状态与线程

主线程跑平台事件循环：AppKit 的 `NSApplication`、WinUI 的 `Application` 与 `DispatcherQueue`、GTK 的
`GtkApplication`。原生控件只在主线程创建与修改，界面状态、比对与补丁也在主线程。Runtime、Core 与产品后端的
异步工作在进程共用的 tokio 运行时上，结果经投递到主线程的入口回到运行时的消息队列；同一轮里的多个消息合并成
一次重绘。读配置仓库这类阻塞工作在运行时的阻塞线程上，内存里的读取（流量总量、连接历史）就地进行。

遥测按需读取：流量总量在主窗口显示期间每秒取一次；连接、命中与活动总量只在显示它们的页面每 2 秒取一次，日志页
每秒取新记录；捕获状态、Core 状态与活动配置除了随事件刷新，每 8 秒再读一次。主窗口关着时这些都停，只剩连接
历史的后台吸收。

只有显示着的页面才拿着自己的大件：连接表的行，以及各页为上一次重绘建好的表格行。换页或关窗时这些都放掉
（`release_hidden_pages`），页面再显示时重读、重建：连接表不显示时不再要更新，它拿着的行会变成历史早已换掉的
旧行；一份满的连接历史或一份很长的规则列表建成的表格行有几 MiB，不放就一直留到应用退出。程序的名称与图标是另一回事：
它们留过自己的行，程序再出现时图标才能立刻显示；留着的超过 512 个时，只留表里的行还在用的
（`forget_unnamed_displays`），否则每个有过连接的可执行文件都会留到应用退出。

### 比对与后端

- 每个节点有组件类型、属性、子节点与可选的键。同层子节点按键匹配（没有键按位置），得出更新属性、插入、移动、
  删除与替换五种补丁；类型不变的节点复用原生控件（`reconcile.rs`），只是行与列的方向或对齐方式变了就替换，因为
  原生的线性布局不能原地改方向。
- 表格与磁贴栅格是虚拟化的：组件树里带着全部行或磁贴，集合共享，同一组只比一次指针；表格的每行也分别共享。
  连接页按历史快照的身份复用未变的渲染行，筛选与排序只重新组织指针；语言、程序展示名或列布局改变时重建对应的行。
  渲染行只留当前筛选与分组结果中的行，换页或关窗时一起释放。程序展示信息按名称与可执行路径去重后查找。
  原生列表需要某一行时才为它建视图，单元格视图按形状复用。后端按键比较新旧两组行，更新可见内容；行数、次序与
  选择的原生更新机制由各平台实现，见 [macOS](../platforms/macos.md#sdk-与验证依据)、
  [Windows](../platforms/windows.md#桌面应用)与 [Linux](../platforms/linux.md#桌面应用)。
- 后端接口（`backend.rs`）：创建、更新与关闭主窗口与编辑器窗口，按补丁更新页面、消息面板、对话框与编辑器的
  组件树，托盘菜单，文件请求，应用菜单（macOS），外观（跟随系统、浅色、深色，强调色用系统的），对回控件，带到
  前面与退出；用户的操作作为 `UiEvent` 报告回来。主窗口外壳的部件（侧栏、工具区、消息胶囊与面板、编辑器的
  命令）是固定的语义部件，各平台按自己的方式摆放。
- 组件：行与列、卡片（含列表里表示正在使用的选中样式）、分栏、间隔、分隔线、文本（标题、正文、说明、大号数字、
  等宽，单行省略或折行）、标记、符号、按钮（主要、次要、无边框、危险、仅图标，可忙碌）、分段选择、摘要行、
  标签值组、表格（列、排序、单选或多选、双击、拖动重排、折行）、磁贴栅格（选中的磁贴带强调色边，可再带对勾；
  可测的磁贴把延迟做成自己的测速按钮）、流量曲线、进度环、占位、滚动区（不拉伸时和内容一样高，容器限高后
  滚动）、
  开关、下拉选择、单选、原地编辑的文字、文本框与搜索框、纯文本编辑框、弹出面板、设置的分组与设置行。页面只给
  文本选样式与色调（默认、次要、更淡、强调、成功、警告、危险），后端映射到平台的语义颜色与字体；图标是 Egrio
  自己的一张表，每项对应三个平台的符号。

### 文本

界面的全部文本在 `text.rs`：每条是按语言返回字符串的方法，缺翻译或参数不符时编译失败，英文复数在方法里处理。
语言偏好变化时重绘所有窗口与托盘；“跟随系统”的判断见产品后端的 `ui_text.rs`。

界面文字只写名称、状态、结果与原因，不是功能说明：控件下不附解释它做什么的说明，提示框只给名称或状态，空页面
只说现状，消息不教用户下一步去哪里、怎么做；占位文字是一个示例值，不是一句话。

## 界面

菜单顺序为活动、节点、配置、规则、连接、日志、设置，侧栏宽度固定，页面占其余宽度，侧栏与页面之间不能拖动。

- 工具区：没有页面标题，侧栏的选中项说明当前页面；左侧是[消息胶囊](#消息)，左边与页面对齐，右侧依次是流量模式、
  系统代理与 TUN 模式开关。开关是带状态点的切换按钮：开着
  为绿点，关着为灰点，进行中或 TUN 会话中断为橙点（中断时悬停说明原因）。局部配置成功保持静默，未完成或失败
  按实际阶段记进消息；节点、模式和网络开关显示匹配当前档案的运行中有效状态。没有配置时开关与流量模式都变灰，
  悬停显示“没有配置”：流量模式属于配置（文件的 `mode`，或在应用里选定、随配置保存的模式），没有配置就
  没有模式，控件不选中任何一项；Core 运行的是当前配置，系统代理与 TUN 只能在有配置时开启，已开启的仍可关闭。
  托盘菜单同样处理，设置页的网络组在组标题旁注明“没有配置”。
- 活动页：流量卡片是主体，图下一行列出活跃连接、进程数与本机代理地址，即 Core 监听的地址（允许局域网访问时是
  `0.0.0.0`）；Core 改用了其他端口时，地址旁有警告标记，悬停说明原因。下方的出口卡片在系统代理或 TUN 模式开启、
  且当前模式经过代理时显示出口 IP（双栈两个地址）、位置与服务商（含 ASN），两族出口不同时位置与服务商注明取自
  哪一族；否则只有一行现状：两层都没有开启，或是直连模式。探测失败只显示“获取失败”。活动页和连接页统一显示“活跃连接”，统计同一 Core 的实时
  TCP 与 UDP 连接，已结束的历史记录不计入。
- 节点页：重在选择。右侧一列卡片是可以显示的条目：全局模式下先是全局出站，然后每个策略组（类型、正在用的
  成员与延迟）：Select 组是所选的成员，自动组（URL-Test、Fallback）是运行中的 Core 报告正在用的那个
  （见 [Core 的策略组](core.md#模块布局)，不是界面按自己的测速推出来的），延迟就是这个成员的延迟；没有 Core
  服务这份配置时自动组不显示成员，卡片的延迟仍按成员的测速结果给出。页面记住上次显示的条目，
  条目没了就显示第一个合适的。其余部分把显示的条目的成员排成磁贴，磁贴与卡片一样高、同一个顶边，两栏上方各只有
  一行说明，标题与数量：“节点 N”数磁贴，“策略组 N”数策略组；条目的名称、类型与正在用的成员已经在选中的卡片上，
  不再重复。没有策略组的配置在全局模式以外没有卡片，
  页面列出全部节点。点按成员就选中它：Select 组选这个成员，全局出站选这一项（策略组在前、Core 能连接的节点在后；
  未选择时 Core 使用第一个策略组），选中的磁贴带强调色边和对勾；自动组的成员只能看和测，正在用的那个带强调色边。点按卡片
  显示它的条目。磁贴与卡片的延迟是独立的测速按钮，测这一个节点或这个组经过的节点，还没测过时显示测速符号。节点
  磁贴只有名称、类型与延迟：写了 `dialer-proxy` 的节点在类型后注明“经 X”（测速经整条链），写了 `test-url` 的
  节点带一个链接图标，悬停显示地址；不支持的节点变淡、不能测也不能选。节点页与托盘共用一份测速结果和一个测速
  队列，同时最多测十个，测速经节点请求它的测速地址（见 [Core 的节点测速](core.md#模块布局)），隐藏与不支持的
  节点不测；失败的原因在磁贴的提示里；节点的地址或测速地址变了，旧结果作废；结果在应用运行期间保留，不写入
  磁盘。
- 配置页：列表上方的“添加配置”打开对话框，可填写名称，从链接下载或从文件导入，或新建空白配置（在编辑器中写入，
  包括粘贴）；导入得到本地副本，不保留链接、不自动更新，需要新内容时重新导入。没有配置时页面只有“还没有配置”
  和添加按钮。下载或导入失败时，对话框在取消按钮那一行的左侧用危险色给出原因（标题与详情的第一行），消息里同样
  记一条。
  配置卡片首行是名称与操作（名称原地改名，编辑、重新应用与删除），次行显示数量和文件内容最近一次变化的
  时间：导入、编辑器保存或应用的控件改写文件时更新，选节点、切换模式与改名不算；一周内显示相对时间，更早的显示
  日期。删除先在删除按钮的位置换成确认与取消，卡片不变形；正在编辑的配置不能删除。
- 规则页：规则列表占满页面，显示类型、内容（规则集显示链接与条目数）、出站与本次启动以来匹配过的连接数；内容列
  里的标记（规则集的条目数、no-resolve）靠这一列的右边排齐，内容在它们前面省略。Core 无论拿到什么数据
  都不会用的规则（类型没有实现，或内容不是这个类型能读的）照常列出，类型是文件里写的那个，内容列带“不支持”
  标记：哪些规则如此由 Core 自己判断（`egrio_core::rule_support_issues`，与编译规则走同一段代码），规则集
  有没有下载、GEODATA 里有没有这个代码不算在内，前者有自己的“未下载”标记。没有
  筛选时直接拖动行调整顺序；筛选按词匹配类型、内容、规则集链接与出站，不分大小写，每个词都要匹配。双击规则在
  对话框里编辑，新增同样在对话框里；对话框的字段不随类型移动，类型用不到 no-resolve 时开关变灰；内容框的
  占位文字是这一类型的示例值；保存
  失败时按钮行左侧用危险色给出原因，再次保存时清掉。工具栏的
  “测试路由”打开弹出面板，输入域名或 IP 后在面板里显示最终出口和命中的规则：Core 运行时按它当前的选择与健康
  状态测试，域名遇到要解析的 IP 规则时像真实连接一样解析，并显示得到的地址；Core 未运行时预览保存的配置，不
  解析域名，面板在第一次测试前注明“Core 未运行”。工具栏还可以更新规则集、重置当前配置的计数。
- 连接页：顶部分段控件选择平铺、按域名或按程序分组，右侧是搜索框，按域名、地址、程序、出站或协议查找，不分大小
  写，输入几个词时每个词都要匹配；分组视图左侧是分组列表，只留有匹配连接的分组。表格只留值得扫读的列（协议、
  平铺时的程序、目标、出站、状态、下载），选中一行在表格下方显示它的详情，其中的规则是连接当时命中的那一行
  原文，与现在的规则列表无关；活跃连接、进程数与上传、下载总量的
  汇总在页面底部。程序名称与图标来自平台归因，见各平台文档。
- 日志页：后端最近的记录，最新的在底部，可看全部或某一级别；列表滚到底时跟随新记录。每条显示时间、级别与完整
  消息（折行），不显示来源。
- 设置页：分网络、通用、外观、关于四组，设置行只有名称与控件。网络组是系统代理、TUN 模式（未就绪时有“准备”
  按钮，准备时按钮原地转进度环）、IPv6、局域网与监听端口。监听信息只展示端口；配置的 mixed-port 不可用、Core
  改用了其他端口时，这一行显示实际端口和原因。IPv6 与局域网开关把值写入当前配置的 YAML；DNS 等其他配置在编辑器
  中修改。规则集尚在准备时，网络组显示准备说明，工具栏的捕获开关显示进行中并可停止；节点与模式
  选择在下载期间禁用。失败后显示原因与重试按钮，失败也记录到消息。通用组是开机自启、静默启动、启动时检查更新、日志级别与 GEODATA：GEODATA 行显示数据的更新时间，没有
  数据时显示“尚未下载”（规则用到时自动下载），“更新”下载两份文件，当前配置用到的文件内容有变化时重启正在运行的
  配置。外观组是主题与语言，关于组是版本号与[更新](#更新)。

配置的 mixed-port 被占用或被系统保留时，Core 改用它之上最近的空闲端口（见 [Runtime](runtime.md#core-与启动输入)），
消息里记一次警告，标题是旧端口与新端口，详情是旧端口不可用的原因；系统代理跟随新端口。

对话框（添加配置、新增或编辑规则）是挂在主窗口上的模态面板，默认按钮在回车上、取消按钮在 Esc 上。

用户切换流量模式或节点时，旧连接全部断开，后续连接使用新设置。开关系统代理或 TUN 模式只增删该层，Core 不重启，
已建立的连接保持，例外见[捕获层切换](runtime.md#捕获层切换)。

## 消息

界面没有浮层通知。操作结果与后台事件写进一条消息记录（`messages.rs`），新消息在标题栏的消息胶囊里一直预览到
读过，完整的记录在从胶囊长出来的消息面板里查看。

- 记录这三类：用户操作的失败与未完成，例如开启 TUN 需要批准、配置未能应用；结果在原地看不出来的操作，例如
  规则集刷新的汇总（更新、未变与失败各几个）、GEODATA 的更新；后台发生的事，例如 TUN 会话中断、恢复或恢复
  失败，系统代理被其他程序改写后的重设或让出，监听端口被占用而改用其他端口，启动时后台下载 GEODATA 的结果。
  结果在原地看得到的成功（添加规则、切换节点、删除配置）不记录。在对话框里做的操作失败时，对话框自己也给出
  原因。
- 每条消息有级别（信息、警告、错误）、来源（TUN、系统代理、配置、规则、GEODATA 等）、标题、可选的详情与时间。
  同一来源、同一标题的消息连续出现时合成一条，记下次数并更新时间。
- 记录只在内存里，最多 200 条，应用退出即清空。它属于界面运行时而不属于窗口：主窗口关闭期间到达的消息，下次
  显示窗口时仍在。
- 消息胶囊在工具区左侧、与页面左边对齐，一直都在：一个小胶囊，里面是铃铛和记录里的消息条数，没有消息时只有铃铛。
  铃铛与条数在各种状态下大小和位置都不变。有未读消息时胶囊向右展开，底色取未读消息里最高的级别，显示最新一条
  未读的标题与详情的第一行，放不下的部分省略，悬停提示给出完整内容；它一直展开到消息读过，指针不会展开或收回
  它。胶囊只向标题与开关之间的空处伸展，宽度变化有动画，别的东西都不移动。面板收起时指针下的胶囊底色略深，
  表示可以点按。
- 点按胶囊打开消息面板。面板就是胶囊自己的底面长出来的：它向右变宽到面板的宽度（不超过开关前的空处）、向下
  长到消息的高度，铃铛与条数留在原处作为面板的抬头，抬头不另显底色；胶囊的着色让位给面板的阴影，消息随之
  淡入。收起时按原路缩回，最后停成胶囊，中途不换层，也不整体淡出。展开与收起中消息按打开时的宽度排好，只被
  面板的边缘裁去，不重新折行。面板浮在页面上，不改变窗口大小，也不移动页面；它和消息一样高，最高 480 点并离
  窗口底边留出边距，再多就滚动。面板顶上是条数与“清空”，下面按时间倒序列出消息，没有消息时是一句说明。打开即
  全部标为已读，页面里的控件交出键盘焦点。再按一次胶囊、按 Esc 或点按面板以外的页面与侧栏都会收起，点按同时
  照常作用于点到的控件；点按工具区的其他控件时面板留着。

## 流量图

速率来自 Core 的流量总量（只增不减，见 [Core 模块布局](core.md#模块布局)的 `telemetry.rs`），不由连接历史的字节
合计推导：历史有上限、可清空，合计会下降。主窗口显示期间运行时每秒读一次流量总量（`traffic_volume`，读取时以
单调时钟打戳），每个点的速率是相邻两次的字节差除以时间戳之差，点按界面自己的时钟定位（`chart.rs`）。Core 未
运行读作零流量；总量下降说明换了 Core 代次，速率从新值重新起算，不出现负值；两次读取相隔超过 1.5 秒时清空序列
重新开始，不跨空档平均。序列保留 30 秒视窗与缩放衰减所需的点。

上下行数字、峰值与曲线在每个点到达时一起更新。视窗终于最新的点，曲线每个点移动一步，两点之间静止：持续平移会
增加窗口合成工作。路径从视窗左侧之外的点开始，序列开始前的时间画作零流量，左缘
不留空白；视窗（含缩放衰减的 4 秒）内没有任何流量时画成底边上的一条直线。纵轴上限取可见点的最大值，移出视窗的
峰值在 4 秒内线性衰减，缩放不跳变。下载和上传使用强调色与成功色的实线与浅色面积，曲线按实际时间间隔做保形
Hermite 插值；缩放不改变屏幕线宽，不显示时间坐标。组件给出两条面积路径、两条描线与可访问的文字说明（当前上下行
速率），后端只画路径。

## 托盘

托盘菜单在界面层按状态描述一次（`tray.rs`），由后端渲染：显示主界面、出站模式、当前配置的全部策略组、系统代理、
TUN 模式和退出，不设置快捷键。出站模式提供规则、全局、直连并勾选当前模式。各策略组直接作为一级子菜单，标题注明
正在用的成员；首项为延迟测试，随后列出成员（隐藏的节点照常列出）及其延迟，Select 组的成员可选，其他组的成员只
列出，两者都勾选正在用的那个；测试与节点页共用结果和队列。延迟低于 200 ms 为绿色，200–499 ms 为橙色，500 ms 及以上或失败为红色，测试中
使用中性色。系统代理与 TUN 模式独立勾选，可同时开启。每个选择写明它的配置与策略组，配置换了以后旧菜单里的点击
不起作用；改动进行期间菜单像窗口的控件一样等待。只有显示的内容变了才重新描述菜单；托盘的操作失败时写进消息
记录。各平台的菜单形式见平台文档。

策略组按组描述（`TrayGroup`）：标题、测速项的状态和成员，成员只带名字、不可用时的标记、能不能选、是否勾选与
延迟；描述在界面层与后端之间共享，后端留着菜单也不复制成员。成员的行由平台在要显示时才做，选择的动作（配置、
策略组、成员）在那一项被选中时才组成。一个节点的显示值由它所在的所有组共享，避免按成员重复构造描述。

托盘直接复用后端的切换与配置操作，关闭主窗口后仍可操作。雪花图标表示系统代理或 TUN 模式是否开启，
图稿与配色见[图标](../../design/icons/README.md)。图标只在这个状态变化时换，平时是静止的：托盘图标常驻，
会动的图标就是一笔常驻的重绘开销。

## 编辑器窗口

- 编辑器是一个独立的窗口，任一时刻只有一个，打开时居中在主窗口上，主窗口关着时居中在屏幕上（Wayland 上由合成器
  摆放）；macOS 与 Linux 沿用上次的尺寸，Windows 每次以默认尺寸打开。它不锁主窗口，两者各自关闭：主窗口关掉后
  编辑器照常。锁主窗口在 macOS 上要在主窗口挂一个 sheet，而挂着 sheet 时
  应用不执行退出（见 [macOS 平台](../platforms/macos.md#sdk-与验证依据)），编辑器开着就退不出应用。
- 再次请求编辑：请求的是正在编辑的配置，或编辑器里有未保存的修改、正在保存时，只把编辑器带到前面；否则编辑器
  换成请求的配置或新配置的模板。正在编辑的配置不能删除，改名后窗口标题随之改变。
- 内容是等宽字体的纯文本框，下面是高度固定的一行状态：没有语法错误、第一个错误的行列与说明（旁边的“定位”把
  光标放到出错处）、正在保存或保存失败的原因；状态变化不移动文本。
- 文本每次修改后用配置解码所用的同一个 YAML 解析器检查。检查在后台进行，同一时间只有一次，连续输入只检查最后
  的文本；有错误时禁止保存，保存时检查若落后于文本，当场再查一次。
- 窗口标题是配置名，有未保存的修改时有标记（macOS 为关闭按钮上的点）；有还原与保存，保存也在 Cmd/Ctrl+S。新
  配置第一次保存时写入，之后同已有配置；还原回到上次保存的文本，新配置没有可还原的。
- 配置文件在别处改动时：编辑器里没有修改就读入新内容；有修改时保留，保存按来源的修订号检查，文件已变则保存
  失败并说明原因。关闭不提示保存，未保存的修改随窗口丢弃。

## 主窗口关闭与释放

关闭主窗口销毁窗口与它的组件树；托盘、Core、消息记录与[日志页的历史](#日志)不受影响，从托盘或再次启动应用显示时
按状态重建。代理客户端的窗口在运行的大部分时间里都关着，所以关闭不保留窗口，也没有让用户选择的开关。macOS 上
应用只在有窗口时出现在 Dock：启动时设为 `NSApplicationActivationPolicyAccessory`（不进 Dock，菜单栏图标照常），
显示窗口时改为 `Regular`，窗口都关闭后改回 `Accessory`，所以静默启动和关窗之后 Dock 里都没有 Egrio，依据 Apple 的
[`NSApplication.ActivationPolicy`](https://developer.apple.com/documentation/appkit/nsapplication/activationpolicy)。

窗口状态与单实例按平台实现：macOS 用 `NSWindow` 的框架自动保存，单实例由 LaunchServices 交给运行中实例的 reopen
回调，不经 LaunchServices 启动的第二个进程拿不到运行锁（`runtime-owner.lock`）就记一行日志退出；Windows 每次
以默认尺寸打开主窗口，以数据目录为键经 Windows App SDK 的 `AppInstance` 把再次启动交给运行中的实例；Linux 只保存
尺寸与最大化（Wayland 不报告窗口位置），单实例先经 `GtkApplication` 的 D-Bus 唯一性，没有会话总线时（GApplication
这时只在本进程注册）由同一个运行锁决定。再次启动都只显示主窗口。

## 启动

桌面启动先取得运行所有权并注册 Runtime，再在主事件循环保持可用时异步执行不依赖配置仓库的 checkpoint/OS 恢复。
恢复完成后才读取配置仓库、初始化日志与 Runtime 宿主，然后创建托盘、按静默启动设置显示主窗口。启动中任何一步
失败都不会撤销之前的网络恢复，也不会启动新的代理会话，应用说明原因后退出。解不出的 checkpoint 记录不在此列：
它恢复不了任何东西，留着却会让之后每次启动都停在恢复这一步，所以恢复之前先把它移出存储并记一条错误日志
（见[租约与检查点](runtime.md#租约与检查点)）；它记录的那次会话不再恢复。

用户上次开着的捕获层在下次启动时重新开启：用户每次开关系统代理或 TUN 模式，开关之后 Runtime 带着的层记进配置
仓库的应用设置（`capture_layers`）；退出与崩溃后的恢复关掉这些层，但不改记下的值。界面起来后，有当前配置才开启
记下的层，开启期间开关显示为开，与用户的开关一样排队；TUN 环境未就绪（例如 macOS 上服务还没被允许）时启动不弹
任何提示、不开 TUN，消息里记一条 TUN 环境未就绪；某一层没能开启时按该层的开启失败记录，记下的值不变，下次
启动再试。

## 更新

`updates.rs` 读 GitHub 上最新的正式发布（REST API 的 `GET /repos/{owner}/{repo}/releases/latest`，草稿与预发布不在内），
版本按主、次、修订号比本构建新才算新版本；发布的文件与流程见[发布](../runbooks/release.md)。

- 通用组的“启动时检查更新”开着（默认开）时，界面起来后在后台查一次：有新版本时消息里记一条“发现新版本 X”，来源
  为更新；没有新版本或查询失败时不提示，失败只写日志。
- 关于组的“更新”行显示已是最新版本、新版本 X 可用、正在检查、正在下载或检查失败。没有已知的新版本时按钮是
  “检查更新”，手动检查失败时消息里记一条错误；有新版本时按钮是“升级”，按钮在检查与下载时原地转进度环。
- 升级下载本机的安装包：macOS 按处理器选 DMG，Windows 是安装程序，基于 Debian 的 Linux 是 deb；发布里没有本机的
  安装包（其他 Linux 发行版）时打开发布页。下载用 `remote_fetch.rs` 的长下载客户端（同一套 URL 与重定向校验，
  上限 512 MiB），按发布里 `SHA256SUMS` 给的 SHA-256 核对，不符即失败；通过后存进应用数据目录的 `updates/`（只留最新
  的一个）交给系统打开。macOS 在 Finder 里挂载 DMG，Windows 以更新模式（`/UPDATE`）运行安装程序，它只显示进度、装完后启动新版（见
  [Windows 安装程序](../platforms/windows.md#安装程序)）；这两个系统替换不了运行中的应用，系统接手后应用照常退出。
  Linux 用桌面的默认程序打开 deb，应用继续运行；没有程序能打开 deb 时记一条升级失败。
- 调试构建认 `EGRIO_UPDATE_FEED`：它指向与 REST API 同格式的 JSON 文件时检查读这个文件，`file://` 的下载地址直接读
  本地文件，在本机就能走完整个流程；发布构建没有这个入口。

## 退出

托盘的退出、macOS 应用菜单的退出与 Cmd-Q、Dock 与系统的退出请求统一进入产品后端 `exit.rs` 的 single-flight
退出协调器：先异步等待 Runtime stop，期间主事件循环保持可用，然后才把实际退出交还平台后端；重复请求共享同一
清理，清理失败保留 checkpoint 并记录错误；显示窗口不能清除退出意图。Runtime-owned packet 任务在实际退出前 join。
普通关闭窗口只释放主窗口，不当作退出。macOS 的应用委托是 Egrio 自己的类，`applicationShouldTerminate:` 在清理
完成前返回 `NSTerminateLater`，完成后回复；Linux 上 SIGTERM、SIGINT 与 SIGHUP 同样进入协调器。

## 日志

桌面关键请求、应用结果和恢复错误统一经标准 `log` 接口记录，不写节点密码、下载链接或完整配置。宿主不注册竞争的
tracing subscriber；`tracing` 的标准 `log` 特性将依赖库事件交给同一 logger，核心库不依赖任何界面工具包。

应用为整个进程安装 `egrio-desktop` 的 `logging.rs` 的 logger，它持有其余规则：

- 级别是应用偏好（存储键 `log_level`），只对 Egrio 自身的记录（`egrio` 开头的模块与 `network`、`rule-providers`
  类别）放开 debug/trace，依赖库始终只输出 info 及以上：它们在这两级的内部细节（每个 HTTP/TLS 帧）会淹没应用
  记录，而通过的每条记录都会进日志页。
- 每条记录写成一行，带本地日期、时间、级别、目标与消息，写到 stdout、日志文件与日志页的历史。
- 日志文件是日志目录下的 `egrio.log`：macOS 为 `~/Library/Logs/com.xinvexo.egrio`，其他系统为本地数据目录的
  `com.xinvexo.egrio/logs`，设了 `EGRIO_DATA_DIR` 时为其中的 `logs`。文件即将超过 2 MiB 时改名为
  `egrio_<日期>_<时间>.log` 并新开一个，改名的文件只留最新的 2 份。改名做不成（别的程序开着它而不许
  改名、目录不让写）不影响记录：继续写在原文件里，每多写 64 KiB 再试一次；目录被删掉时，下次打开文件
  会重新建。
- 日志页的历史保留最近 500 条记录（序号、时间、级别、目标、消息），序号跨清空连续；清空只清历史，主窗口重建后
  仍看得到之前的记录。更早的记录只在日志文件里。

## 测试与验证

- `egrio-ui` 的测试不依赖平台：页面测试给定状态，断言组件树里的文本、状态与消息；另有运行时、比对、流量曲线、
  连接合并与日志记录的测试。
- 带 `test-control` cargo feature 的构建开一个只允许同一用户连接的本地控制口，每行一条命令、每条回答一行：切换菜单、
  按工具栏按钮、按标题点按钮、在窗口的某一点单击或双击、放下表格的行、滚动、按键、输入与输入法组字、菜单命令、
  托盘菜单的读取与选择、窗口截图与视图树；截图由应用自己把窗口画进位图，不需要屏幕录制权限。macOS 与 Linux 的是
  数据目录里的 `test-control.sock`；Windows 的是命名管道（管道不在文件系统里，名字按数据目录取，写在数据目录的
  `test-control.pipe` 里），只有这个 feature 的构建带 PNG 编码器，用来写 `RenderTargetBitmap` 画出的截图。
  命令列在各平台的 `test_control.rs`，平台之间的差异也写在那里：Windows 上弹出面板的控件属于页面的 surface，
  所以没有自己的作用域、按种类数控件时把它们一起数；文件选择器是 shell 的对话框，测试构建不打开它，直接等
  `answer-file`；滚动在下一次布局才生效，同一批里的 `dump` 读到的还是旧位置。发布包不带这个 feature；
  `cargo xtask package --test-control` 生成与发布包同样签名、带控制口的 macOS 验收应用。
- 开发中的实例设 `EGRIO_DATA_DIR` 使用单独的数据目录，配置、状态与 Runtime 运行锁都不与已安装的应用共用，开发
  实例里不开启捕获层。系统验收按[捕获层验收](../runbooks/capture-layers.md)。
